## Problem And Desired Outcome

- Problem: Prisma 7's default generator is `prisma-client`, which writes the client into the application (custom `output`). `repository_prisma` loads `@prisma/client` when it is imported, and that package only works with the deprecated `prisma-client-js` output. An application on the new generator cannot even import the library (Reproduced), and the library's types become `any` (Measured). Prisma says `prisma-client-js` "will be removed in future releases".
- Affected actors or systems: Node.js applications (ESM or CommonJS) that use `repository_prisma` with Prisma 7 and SQLite.
- Desired outcome: an application using the `prisma-client` generator can use every library feature with full type safety after a short, one-time setup, while applications on `prisma-client-js` keep working with no change.
- Observable definition of success: a real app on the `prisma-client` generator (ESM and CJS) imports the package, registers its client, and runs initialization, repositories, the `prisma` proxy and both transaction styles against SQLite; its type check rejects wrong fields and models; the existing prisma-client-js suite and package smoke still pass.

### Out Of Scope

- Prisma 8 (new runtime package, PostgreSQL-only guide so far).
- Non-SQLite datasources and supplying a driver adapter (FU-004 of repository-prisma-1).
- Upgrading any consumer (FU-001 of repository-prisma-1).
- Removing `prisma-client-js` support, or a breaking change for its users.
- Version bump, tag, publish, GitHub release.
- Other `prisma-client` generator runtimes than Node.js (edge/workerd/bun-specific outputs).

### Non-Goals

- Making the library's declarations pass `skipLibCheck: false` in a prisma-client-only app (see DEC-005).
- Supporting several different Prisma clients at the same time in one process.

### Preserved Behavior Boundary

- BEH-003 in full: prisma-client-js apps need no code, config or type change; all ACs of repository-prisma-1 and repository-prisma-2-loose-ends keep passing.
- BEH-004: existing error codes and messages unchanged; messages stay free of URLs, credentials and paths.
- Peer dependencies, Node range, SQLite-only rule, driver adapter, connection gate, DateTime storage format, logging policy, lifecycle and forwarding semantics unchanged.
